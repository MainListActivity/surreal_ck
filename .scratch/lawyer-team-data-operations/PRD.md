# 律师团队数据完善与运营闭环

## 问题陈述

律师团队已能通过工作簿、数据表、模板和 Excel / CSV 导入维护台账，但从“数据进入系统”到“数据经过核对、缺失材料有人跟进、处理结果经过复核”的过程仍需要产品化。团队负责人需要明确知道哪里存在问题、依据是什么、谁负责处理，以及怎样确认完成。

平台运营人员需要知道团队在哪个启用步骤遇到困难，以及帮助之后是否改善。目前本次浏览只能证明当前工作区可见的功能，不能据此推断全站使用情况或认定未看到的功能不存在。注册数、工作簿数和 AI 对话量不足以说明律师团队是否获得实际收益。

## 解决方案

以“债权台账导入 → 数据体检 → 确认修正或派单 → 真人复核 → 查看完成情况”为首期纵切。复用已有导入、字段映射、数据表运行时、资源关联和协作能力，增加可持久恢复的批次与问题处理闭环。

建设顺序：

1. P0：增强导入恢复能力，交付数据体检及修复清单。
2. 首期闭环必需：交付最小真人派单与复核能力。虽然上一轮将完整协作工具列为 P1，这个最小子集是首次复核的必要条件。
3. P0：工作区启用进度与可解释的指标；平台侧只展示有来源、获得授权的摘要及待跟进事项。
4. 首期运营能力同时通过独立运营页面和 MCP 暴露，供 agent 主动发现问题、维护跟进队列和检查结果。后续 P1：完整模板运营、支持工单、外部自动触达和更多业务模板。此次记录方向，不作为首期交付要求。

客户数据完善闭环不依赖 AI 可用。运营方向明确为 agent 主动运营：MCP 提供可组合的业务动作，独立运营页面承载可视化、授权配置、审阅和人工接管。两者使用同一领域服务，agent 不需要依靠模拟点击操作后台。现有 AI 分析继续提供建议，不替代律师复核结论。

## 实现决策

### 复用边界与现状

- 已有多工作表导入控制器、模板字段别名映射、类型转换、逐行拒绝与重试能力。增强这些模块，不另建导入引擎。
- 数据表运行时是动态业务数据表的唯一执行入口。扩展其批次写入、全范围读取及带前提的修正能力，页面不自行访问动态物理表。
- 当前运行时默认窗口为 500 条。体检不得将该窗口冒充完整数据集；全范围读取应有稳定分页、取消、进度与中断标记。
- 已有债权审核建议和资源关联。首期确定性检查与持久问题清单补充这些能力，不重新实现 AI 分析。
- 业务协作使用“派单”；复用既有派单领域，补充真人受理与复核所需能力，不将模板中的历史待办数据直接当作已有完整派单引擎。
- 管理员通过邮箱预创建普通成员，首次登录完成加入；不增加邀请 token、邀请邮件或另一套成员身份流程。
- 平台运营人员复用独立运营身份和 capability 体系。已有配额运营能力不能隐式赋予案件读取权；平台看板扩展已经存在的独立运营端，MCP 扩展已有 OAuth 运营入口；不重新建设后台、登录体系或第二个协议入口。

### 导入批次

- 保存批次身份、工作簿、源文件摘要、工作表与原始行号、映射版本、写入记录引用、逐项结果及完成时间。源文件全文不默认持久保存。
- 确认前预览零业务写入；确认后批次状态至少区分处理中、完成、部分失败、失败、结果待核实与已撤销。
- 幂等身份由批次和源行共同确定。文件摘要仅用于提醒重复文件，不阻止用户明确发起合法的新批次。
- 保留已有事务边界：新建工作簿内的新数据表按现有原子提交路径执行；映射已有数据表可以逐表完成，界面不得宣称整个多表导入必然原子。
- 重试前查询已持久结果，结果待核实不能直接盲写。业务记录与对应批次行回执应在同一事务提交。
- 首期仅新增记录，不支持导入覆盖更新已有记录。拒绝行导出保留原始行号与原因；导出用于表格软件时，对可能被解释为公式的文本作安全编码。
- 撤销先预检，仅删除该批次新建且未被后续修改、未被批次外记录引用的记录；存在阻碍时整体拒绝并列出原因。用户重新确认后，在事务内重验前提。撤销保留批次及审计，不隐式删除字段、数据表或工作簿。

### 数据体检与问题处理

- 首期规则类型限定为：必填缺失、符合既有字段约束的格式校验、配置字段组合的精确规范化重复候选、引用目标缺失、模板声明的字段间一致性比较。不开放任意脚本或自定义查询执行。
- 法律字段、业务阈值和解释文案保存在模板数据中，通用体检模块不硬编码债权法律判断。不存在的字段或无权读取的关联目标标为无法判断，不能误报缺失。
- 每次体检固定规则版本、范围、开始和结束时间；记录问题所依据的数据版本或指纹。跨页期间发生变化时将受影响结论标记待重检，不宣称具有未实现的数据库快照能力。
- 体检运行至少区分处理中、完成、部分完成、失败和取消；仅完整扫描成功才显示“此范围未发现问题”。
- 问题具有稳定身份：记录或候选记录组、规则身份及规则版本。同一版本重扫合并问题，不重复创建派单；规则升级保留旧结果及与新运行的关联。
- 每个问题保存类别、解释、记录/字段引用、状态、证据指纹和处理历史。原始敏感值只在工作区内按需要保存，不复制到运营摘要。
- 状态为待处理、处理中、待复核、已关闭、不适用；待复核可以被退回处理中。不适用必须填写理由；重扫发现相关数据变化时重新打开或标记待重检。
- 修复操作绑定预览的数据前提和明确字段差异；事务内重验后再写入，前提变化返回冲突。疑似重复不自动合并或删除。
- 体检问题关闭表示质量检查已处理，不表示债权法律审查通过；不能自动改变债权审核结论。

### 派单与审计

- 一个派单可以关联多个问题，每个问题同时最多存在一个活动处理派单。首期受理人为同工作区的真人用户。
- 派单保存负责人、截止时间、复核人和完成条件；提交处理说明后进入待复核，由指定复核人或工作区管理员处理。自我复核不计入多人协作指标，历史保留实际操作者。
- 复核通过必须重新核验问题依据：确定性规则应已通过，或由复核人显式确认例外并填写理由。退回保留意见。
- 关闭问题、更新派单和记录审计需要保持原子一致；重复点击不能产生第二份结果。历史作为追加事件保留，不允许普通编辑覆盖。
- 到期提示首期在应用内展示；外部邮件、短信和自动催办不在本期。

### 身份、存储与架构

- 批次、体检运行、问题、派单和业务审计保存在对应 workspace database。按现有版本化迁移机制追加结构；关联归属使用引用字段，具有独立业务生命周期的关系才考虑边。
- 浏览器通过调用者会话直连执行 DML 和 LIVE。权限在数据库 schema 中强制；普通成员不能 DDL，管理员结构操作仍由 access 类型决定。
- 不增加工作簿、记录、问题或派单的后端 CRUD/LIVE 代理，不引入 service JWT，不使用 root 扫描客户台账来生成运营报表。
- 本文定义概念性数据契约，不写 SurrealQL。实现迁移或查询前必须按仓库要求加载相关技能并验证真实数据库行为。

### 启用进度与运营摘要

- 工作区内根据持久批次、体检、派单和成员状态计算启用进度，刷新后可恢复。界面事件仅作诊断，不作为业务成功的唯一证据。
- 首期跨工作区运营摘要使用“工作区管理员预览并主动提交”的窄动作，包含摘要版本、统计周期、去重标识、数量、阶段、更新时间及允许共享的错误类别。不包含文件名、案件名、记录内容、材料正文或成员邮箱。
- 后端验证调用者的工作区成员与管理员身份、字段白名单和大小限制，存入运营摘要投影；这是显式授权的摘要接收，不是业务 CRUD 代理。客户端摘要标记为团队提供，不能用于收费、权限判断或冒充可信服务端全站计量。
- 运营读取按独立 capability 授权，客户端不能指定任意工作区冒领身份。重复提交只更新同一份投影；撤回共享后停止展示并清除摘要内容，保留最小撤回审计。
- 团队摘要和运营跟进事项复用运营身份及控制面存储边界；不因本规格额外扩张 root 的客户业务访问范围。该部分依赖既有运营身份与独立运营端就绪。
- 运营待跟进事项保存工作区索引、原因类别、负责人、处理状态、人工或 agent 动作与结果。它不自动触达客户，也不能通过操作详情钻取未授权案件。
- 每个指标展示统计窗口、分母、来源和新鲜度；没有上报显示未知。未上报团队不计为未激活或流失。

### 独立运营页面、MCP 与主动运营 agent

- 三个入口分工：客户页面处理台账和真人复核；独立运营页面展示跨工作区授权摘要、跟进队列、行动历史、待审动作和暂停控制；MCP 提供同一运营能力供 agent 调用。
- 运营领域服务为统一执行边界。页面 API 与 MCP 只是适配层，复用授权、数据契约、前提检查、幂等和审计；MCP 不直接访问客户业务表，不提供任意 SQL、任意 HTTP 请求或数据库凭证工具。
- 首期工具契约覆盖：列出运营机会、读取团队摘要、列出跟进事项、创建/认领/更新跟进事项、提交行动建议、读取执行结果。查询返回游标、来源和更新时间；变更接受幂等键及预期版本，返回稳定动作标识、状态和下一步。
- 使用现有 OAuth 运营身份；每次调用重验当前 capability，token scope 只能收窄权限。记录授权主体和 agent 执行标识，不把模型提供的身份参数当作鉴权依据。
- 首期主动循环：按配置周期或变更游标读取授权摘要 → 识别待跟进事项 → 去重并认领 → 执行允许的运营动作或形成待审建议 → 到期检查结果 → 更新状态与检查点。模型解释不是业务成功证据，结果需要工具返回及后续状态支持。
- 授权范围内的读取、摘要分析、内部跟进事项维护和建议草稿可自动执行，不要求逐次人工确认。涉及客户数据写入、外部消息、商业权益调整等动作不因开放 MCP 自动获准；只有未来具备相应工具及明确动作授权时才能执行。
- 每项行动记录触发原因、使用的摘要版本、授权主体、执行者、输入摘要、幂等键、状态、结果及错误类别；不得把 token、案件正文或不必要的模型推理写入日志。
- 多 agent 认领使用有时限的占用和版本前提；中断后可恢复，租约过期可重新认领，但已有成功动作不重放。重试有上限，持续失败进入待人工处理，避免无限循环。
- 运营页面能够暂停后续自动执行、查看失败原因和接管待办。暂停不伪装成撤销已经发生的动作；恢复继续沿用检查点和幂等历史。
- 首期可由外部 agent 使用现有 MCP 驱动，提供可持久化的运营运行记录与检查点；不新增常驻 agent 调度平台，不假定客户端断开后仍在运行。部署自动运行时需明确运行宿主、频率和预算。
- 管理员主动共享的摘要是首期输入边界。agent 可主动处理已有摘要，但不能把陈旧摘要当实时监测；自动持续摘要来源后续单独设计，不借 root 扫描弥补。

### 指标口径

- 首次复核耗时：同一工作簿首次确认导入的时间至首个关联问题完成真人复核的时间；没有体检问题或尚未复核时分别标记不适用、未完成，不填零。
- 导入失败率：确定终态为失败或部分失败的批次占确定终态批次的比例；同时展示拒绝行比例，结果待核实单独列出。
- 问题解决率：固定体检运行所产生问题中，经复核关闭的数量占该运行问题总数；不适用单列，不随扫描刷新悄悄更换分母。
- 多人协作：同一处理链出现至少两个不同真人用户的有效操作；虚拟员工和同一人的多个浏览器不算新增协作者。
- 次周更新：首次成功导入后的第 7 至第 13 个自然日内，是否存在真实业务记录新增或修改；采用工作区展示时区，保存 UTC 时刻。无数据可证明时显示未知。
- 首期用试点基线评估改善，不凭空承诺固定转化率或节省时长。

## 测试决策

- 主要验收边界是用户可见的完整纵切：在隔离工作区中导入固定台账，定位体检问题，确认修复或派单，由另一真人复核并看到进度更新。验证持久结果和用户可见错误，不断言内部方法调用次数或组件私有结构。
- 复用已有导入控制器、模板导入与数据表运行时的公开接口。仅为全范围体检与处理闭环提供一个集中编排接口，不为每条规则建立新的跨模块测试缝隙。
- 先例包括：多工作表导入控制器的部分失败和取消测试、模板映射的逐行拒绝测试、工作簿模板实例化集成测试、真实 SurrealDB 事务提交/回滚测试、模板权限集成测试，以及配额运营授权测试。
- 数据库集成测试使用临时工作区、管理员和普通成员真实会话；root 只用于测试环境搭建清理。验证跨工作区拒绝、DML/DDL 边界、越权复核拒绝及撤权后读取失败。
- 固定夹具覆盖至少 501 条记录、缺失值、无效日期金额、重复候选、断裂引用、合法重复申报、多工作表部分失败和零问题台账，证明不会仅检查首屏。
- 核心失败场景：确认前零写入；断线后的结果核实；相同批次/源行重放；仅失败行重试；修复前并发编辑冲突；撤销阻碍；重复派单和重复复核幂等；重扫保留历史；规则变更使旧依据失效。
- 运营边界另用窄动作契约测试验证摘要白名单、身份绑定、去重、撤回与 capability；不把浏览器伪造事件当作可信业务成果。缺失数据必须显示未知。
- 同一运营用例通过页面 API 与 MCP 执行应得到等价授权、状态与审计。覆盖 OAuth scope 收窄、实时撤权、多 agent 竞争认领、租约过期、中断恢复、重复调用、审批前提变化、暂停后不再发起新动作以及重试耗尽转人工。模型输出用固定替身验证，不以真实模型调用作为协议验收条件。
- 指标使用冻结时钟验证统计窗口、分母、不同操作者和时区边界；不能用无关页面浏览补足留存。
- 浏览器验收使用脱敏夹具，不对线上真实台账执行测试性写入。点击详情出现的单次遮挡只作为待复现线索，不作为已确认缺陷或本规格验收前提。
- 已向用户提出上述测试边界核对；截至编写时尚未收到调整意见，按推荐边界起草，不表述为用户已经确认。

## 不在范围内

- 完整模板发布平台、模板升级迁移、支持工单系统、外部客服或 CRM 集成；独立运营页面和 MCP 的本期运营动作扩展包含在范围内。
- 无人值守清洗、自动合并重复债权、自动法律裁决或自动覆盖审核金额。
- OCR、扫描件抽取、新文件存储体系、跨工作区案件搜索和全站客户数据扫描。
- 新增独立派单引擎、虚拟员工自治调度或新 AI 工作流；现有 AI 能力不作为确定性闭环依赖。
- 套餐、收费和资源权益调整；配额错误沿用现有契约。
- 自动采集全站使用事件和未经管理员预览的业务摘要上传；后续若需要可信自动计量，应单独制定来源与授权设计。
- 实施代码、生产迁移、部署或向律师团队发送消息；本次只发布规格。
