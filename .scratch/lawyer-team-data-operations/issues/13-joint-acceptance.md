## 复现

在仓库里执行：

```bash
cd web && RUN_LOCAL_SURREALDB_JOINT_ACCEPTANCE=1 pnpm exec bun test ./src/lib/lawyer-team-joint.integration.test.ts --preload ../server/test/setup-env.ts
```

测试自己启动内存版 SurrealDB，并在 `127.0.0.1:18081` 提供与测试环境变量一致的 JWKS。引擎启动带 `--allow-net 127.0.0.1`，否则拉不到 JWKS。客户会话使用工作区模板里的 `admin` JWT 与 `participant` RECORD access，不用临时 SIGNIN。运营请求用同一把密钥签发，并走现有的 OIDC 校验。

2026-09-23 在本机 SurrealDB 3.2.3 上通过：1 个测试，47 个断言，约 4 秒。测试文件是 `web/src/lib/lawyer-team-joint.integration.test.ts`。

## 限制

- 旧配额闸门默认是 plus（1 张表、3 个字段）。夹具在建表前把当前工作区改绑到 max。记录条数闸门没有挂在插入事件上，所以 502 条可以导入。
- 重扫会把待复核问题的处理人清空。本链路的第二名复核人是工作区管理员，Owner 会话可以完成复核。
- 带有本库 `db` 声明的 participant 令牌，即使连接时指定了另一个库，会话仍停在本库：看不见另一工作区的标记，仍能看见本库的 502 条债权。
- 动作执行到一半被进程杀掉的恢复，仍由运营运行集成测试覆盖。本链路验证的是完整跑完后下一轮不重放这 3 个动作。
- 没有写生产库，没有发外部消息，没有部署，也没有创建定时作业。
