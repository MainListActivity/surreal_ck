# 01 — 导入批次持久化与安全重试

**What to build:** 律师确认导入后能够查看持久的逐表、逐行结果，刷新或断线后核实结果，只重试失败行而不重复创建记录。复用现有 CSV / XLSX 解析、字段映射和数据表运行时。

**Blocked by:** 无 — 可立即开始

**Status:** done

- [x] 导入前显示工作表、字段映射、类型转换差异和原始行号；确认前取消零业务写入。
- [x] 保存批次、映射版本、源行身份、目标记录引用和逐项回执；业务记录与对应成功回执同事务提交。
- [x] 覆盖处理中、完成、部分失败、失败和结果待核实；刷新可恢复，超时先核实已提交结果，不盲写。
- [x] 相同批次与源行重放幂等；文件摘要仅提示重复文件，用户可明确建立新批次。
- [x] 保留新工作簿原子提交、已有数据表逐表完成的现有语义；不实现导入覆盖更新。
- [x] 失败行可下载并修正重试，保留行号及原因，成功行不重写；导出对可能触发表格公式的文本安全编码。
- [x] 普通成员可向获准的已有数据表写入，结构创建由管理员执行；配额失败保留已确认结果并给出恢复入口。
- [x] 通过公开导入接口及真实数据库验证取消、部分失败、重复提交、提交后断线与权限隔离；界面能演示恢复过程。

## 共同约束

- 父规格为“律师团队数据完善与运营闭环”；本票不改变其范围与身份边界。
- 复用现有模块、领域词汇和 ADR；必要的局部预重构先保持现有行为测试通过，再增加本票能力。
- 按实际涉及内容加载仓库规定的技能；业务数据使用调用者会话，权限落在数据库，不新增业务 CRUD/LIVE 后端代理。
- 交付包含所需持久化、授权、界面或工具入口与行为测试，不以单一层实现作为完成。
