# 11 — 自动运营授权与暂停控制

**What to build:** 运营人员按工作区与动作设置 agent 自动执行范围，在独立页面暂停、恢复或撤权，每次 MCP 执行都遵守最新控制。

**Blocked by:** 09 — 运营机会与跟进队列

**Status:** done

- [x] 配置页展示授权工作区、动作白名单和当前启停状态；服务端校验配置者权限，配置不能授予其本身没有的能力。
- [x] 有效权限取实时 capability、OAuth scope、工作区范围与动作策略的交集；读取和变更都在执行边界重验。
- [x] 授权内读取、内部跟进维护和草稿无需逐次批准，未授权动作明确拒绝；不新增全能 agent 身份或凭证透传。
- [x] 暂停阻止后续自动动作，已开始或完成的动作如实显示状态，不伪称回滚；恢复不清除幂等历史。
- [x] 记录配置与暂停操作历史，页面可查看并操作；MCP 返回结构化暂停、撤权或范围错误。
- [x] 测试旧 token 撤权、scope 收窄、工作区范围、暂停与动作竞争、恢复后重复提交，人工接管不依赖 agent 在线。

## 共同约束

- 父规格为“律师团队数据完善与运营闭环”；本票不改变其范围与身份边界。
- 复用现有模块、领域词汇和 ADR；必要的局部预重构先保持现有行为测试通过，再增加本票能力。
- 按实际涉及内容加载仓库规定的技能；业务数据使用调用者会话，权限落在数据库，不新增业务 CRUD/LIVE 后端代理。
- 交付包含所需持久化、授权、界面或工具入口与行为测试，不以单一层实现作为完成。
