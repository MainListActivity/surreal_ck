# 09 — 运营机会与跟进队列

**What to build:** 运营人员和 agent 从授权摘要发现需要帮助的团队，在同一跟进队列创建、认领、更新事项，避免重复跟进。

**Blocked by:** 07 — 授权摘要共享与运营查询

**Status:** done

- [x] 页面和 MCP 支持机会列表、摘要定位、跟进事项创建和状态更新；返回来源版本、新鲜度、稳定游标和下一步。
- [x] 以工作区、原因和相关周期定义稳定去重身份，重复提交不重复建项；陈旧或未知摘要不被判定为流失事实。
- [x] 认领使用有期限租约和预期版本，多 agent 竞争只有一个成功；过期可重新认领，旧持有人不能继续更新。
- [x] 保存原因、负责人、状态、到期检查时间及结果；每个变更验证 capability、scope 和幂等键。
- [x] 客户撤回摘要后不可继续展示其内容；已有事项保留最小处理历史并标记来源不可用，不继续派生内容。
- [x] 页面与 MCP 契约测试覆盖分页、重复创建、竞争认领、租约过期、来源撤回及权限拒绝；只维护内部事项，不发送外部消息。

- 父规格为“律师团队数据完善与运营闭环”；本票不改变其范围与身份边界。
- 复用现有模块、领域词汇和 ADR；必要的局部预重构先保持现有行为测试通过，再增加本票能力。
- 按实际涉及内容加载仓库规定的技能；业务数据使用调用者会话，权限落在数据库，不新增业务 CRUD/LIVE 后端代理。
