# 06 — 真人派单与复核闭环

**What to build:** 负责人把体检问题交给同工作区真人处理，处理人提交说明和材料引用，复核人通过或退回，团队看到一致的完成状态。

**Blocked by:** 05 — 问题修正与并发保护

**Status:** done

- [x] 复用派单领域，支持多个问题关联一个派单，每个问题最多一个活动派单；设置负责人、期限、复核人和完成条件。
- [x] 处理人可定位记录和已有资源关联，提交说明进入待复核；不新增材料存储体系或独立派单引擎。
- [x] 指定复核人或管理员可通过或退回；通过前重验规则依据，例外必须显式说明理由，普通无权用户不能越权复核。
- [x] 问题关闭、派单完成和追加审计同事务提交；重复派单、提交与复核幂等，退回保留历史。
- [x] 保留真人操作身份，自我复核不计多人协作；应用内展示期限，不发送外部提醒。
- [x] 两个真实用户会话可演示修正、提交、退回、再提交、通过；覆盖并发变化、重复操作、跨工作区和撤权。

## 共同约束

- 父规格为“律师团队数据完善与运营闭环”；本票不改变其范围与身份边界。
- 复用现有模块、领域词汇和 ADR；必要的局部预重构先保持现有行为测试通过，再增加本票能力。
- 按实际涉及内容加载仓库规定的技能；业务数据使用调用者会话，权限落在数据库，不新增业务 CRUD/LIVE 后端代理。
- 交付包含所需持久化、授权、界面或工具入口与行为测试，不以单一层实现作为完成。
