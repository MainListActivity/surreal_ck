## 门行为演练（前任 vanilla 本地栈历史记录，待 fork 复验）

1. **agent 自治门**：`kind=agent` 运营主体（mallory，具备 content.* 能力）调用 `submit_batch`/`publish_batch` → 一律 `out_of_scope: 该工具不在 agent 自治动作范围内`。AI 员工不能提交/发布平台内容，生产同样适用。
2. **平台侧准入门**：未注册来源 `unregistered.test` 的批次提交 → 条目级 `rejected` + `source_not_registered`（不波及同批次其他来源）。
3. **提交许可边界**：submit-only 许可来源提交 → `accepted`；该来源无 publish 权。
4. **发布许可门**：对 submit-only 来源批次走 inspect（validationRevision=1）→ `publish_batch` → **publication status=failed，条目逐条 blocked + `source_not_authorized`**；`search_content` 复核 0 条已发布——平台结构上拒绝发布无发布权内容，"运营只发布已审阅条目、默认不自动发布"由三重机制保证（CLI 无发布通路、agent 自治门、来源许可 allowedActions）。
5. **401/撤权**：无效 token 的提交 pass → 快照与批次本地 staged、`remoteBlockedReason=auth`、零远端副作用；`--reauthorized` 恢复 → 成功提交（batch_f25d6d07）。
6. **采集器准入门**：未准入 host、flk、wenshu → `AccessRestrictedError`（"未通过 LCAQ-01 准入，采集器拒绝工作"/robots 禁采原文）。
7. **协议回归**：adapter+incremental 套件 41 pass/0 fail；`content/service.test.ts` 10 pass/0 fail；LCM-10（合成 e2e，已 verified）覆盖 publish→授权读取→撤回/恢复完整协议腿。`store.integration`（RUN_LOCAL_PLATFORM_CONTENT_TESTS=1）3 用例在本地 fork 引擎超时——与今日干净 main 基线逐项一致（既有环境问题，非本分支引入）。
