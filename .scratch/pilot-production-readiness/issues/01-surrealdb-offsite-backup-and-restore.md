# 01 · 生产 SurrealDB 异地自动备份与恢复演练

**目标**：为唯一云主机上的生产 SurrealDB（`_system`、全部 workspace database、`platform_content`）建立加密异地自动备份与定期恢复演练机制，彻底消除种子律所保密案件数据的单点丢失风险。

## 范围

1. **备份方案与脱敏加密**：编写受控备份脚本与 runbook（`docs/runbooks/surrealdb-offsite-backup.md`），每日自动导出并校验完整性，使用独立加密密钥加密后上传至异地对象存储（如独立 R2 bucket 或第二存储介质）；设定保留策略（如近 7 日每日 + 近 4 周每周）。
2. **绝不泄露凭证**：备份凭证仅存宿主机受限目录（0600），不进仓库、不进日志、不进员工环境。
3. **隔离恢复演练**：在独立临时环境使用同一版本公司 SurrealDB fork（`4.0.1-native-quota.1`）执行完整恢复演练，校验 `_system`、示例 workspace 记录数与关键索引完整可用。
4. **告警与登记**：备份失败写入明确退出码/日志并接入现有运维健康检查；如新增定时单元须按 `company-landscape.json` 规程先授权登记，优先复用既有运维定时框架。

## 非目标

- 不搭建多活分布式数据库集群；不在演练中直接覆盖生产数据目录。

## 独立验收标准

- [x] 落盘 `docs/runbooks/surrealdb-offsite-backup.md`，覆盖备份触发、加密密钥保管、保留周期、恢复步骤与 RPO/RTO 目标。
- [x] 在隔离测试库完成至少一次「导出 → 加密上传 → 拉取解密 → 空白 fork 实例恢复 → 查询核对」全链路演练，且记录校验和与耗时。
- [x] 核查隔离演练的备份日志与产物，确认零明文 root 密码、令牌或未加密客户数据暴露。
- [x] 生产手工全量备份产出经 R2 回读核验的加密归档，异机全量恢复对账通过。
- [ ] 挂接既有运维定时框架，验收首次每日定时触发、可核验回执和告警联动。

**依赖**：无（高优先级，可立即开工）。  
**验证方式**：隔离公司 fork 恢复实测 + 生产首次备份归档回执。

## 2026-11-27 UTC 实测记录

- 生产 TiKV 首次全量加密备份写入 R2，回读 SHA-256 一致。对象 `surrealdb-20261127T121836061943Z.cms` 为 202,381,029 字节，保留 35 天，脚本耗时 342.26 秒。解除围栏后三处生产入口均返回 200。
