# 07 · 私有受控 SFU 媒体平面与大规模大会承载

**目标**：引入公司自托管的私有 SFU 媒体服务，突破纯 P2P Mesh 的 6–8 人上限，让 10–200+ 人的正式外部会议（如债权人会议）在手机和桌面浏览器上都能低流量、低卡顿稳定运行，且媒体流始终留在公司受控主机，不经过第三方公有会议云。

## 范围

1. **私有 SFU 部署与受控接入**：按 `01` ADR 选型（如自托管 LiveKit / mediasoup）部署单实例私有 SFU；日常会议默认关闭录制，正式存证会议仅开放轻量轨道直录（Track Egress，严禁在业务库主 VPS 上直接跑高 CPU 无头浏览器实时合成转码）；严格限制管理 API 仅允许 Bun origin 内网访问；在 `company-landscape.json` 按规程登记服务与端口。
2. **短时房间令牌签发与回收**：Bun origin 按会议场次和参会角色（主持人 / 发言人 / 只听参会人）签发最小权限短期 SFU token；支持服务端主动调用 SFU API 踢出指定参会人、强制关闭其音视频轨道与销毁房间。
3. **自动拓扑选择与移动端省流**：正式外部会议默认走私有 SFU；日常会议人数超过阈值（如 > 4 人）或创建时指定大会模式直接走 SFU；移动端默认仅订阅当前发言人音频 + 屏幕共享画面，提供一键「纯音频省流模式」与弱网断线自动重连。
4. **容量与降级验证**：实测单台受控主机承载上限（明确 CPU/带宽水线），超容量上限时拒绝新建大会并给出明确中文提示，不拖垮同一主机上的业务库或源站服务。

## 非目标

- 不接入任何第三方公有云音视频 SaaS；第一阶段不做多地域 SFU 集群（单机实测容量并给出明确上限，超出再按需扩容）。

## 独立验收标准

- [ ] 私有 SFU 启动后，管理端口仅对本机/内网可达；客户端无法绕过 Bun origin 自签令牌加入任意房间（负例测试覆盖）。
- [x] 只听角色（listener）令牌在 SFU 侧强制禁止发布音频/视频/共享轨道，即使客户端直接请求发布亦被隔离实例上的真实 LiveKit 拒绝。
- [ ] 服务端执行踢人或结束房间后，被踢端在 SFU 媒体平面立即断流，不可凭旧 token 重连。
- [ ] 模拟 30+ 并发参会连接（1 路主持人音视频 + 1 路屏幕共享 + 29+ 路订阅接收）持续 15 分钟压测，记录主机 CPU、内存、带宽占用及丢包/恢复表现，证明不影响同期 Hono API 健康。
- [ ] 手机端浏览器支持一键切换纯音频省流模式，切网（Wi-Fi ↔ 4G）后自动重连且无需重新核验身份。

**依赖**：`01`、`04`、`05`。  
**验证方式**：SFU 权限负例测试 + 自动化并发模拟压测报告 + 真实手机浏览器切网实测。
