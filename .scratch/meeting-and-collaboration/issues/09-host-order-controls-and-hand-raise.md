# 09 · 正式会议主持人秩序强控（禁自开麦、举手发言与锁定）

**目标**：为受控外部正式会议补齐强秩序管理能力，确保数十至数百人在线时不会出现外部人员误开麦噪音、抢占屏幕共享或扰乱会场秩序的问题。

## 范围

1. **默认静音且服务端强制锁麦**：正式外部会议默认开启「全体静音且禁止自行解除」；外部参会人初始仅获 SFU 只听权限，即便篡改前端请求也无法推流。
2. **举手排队与点名发言闭环**：外部参会人点击「举手申请发言」进入主持人侧有序队列（展示名册实名与举手时间）；主持人点击「允许发言」后，服务端动态提升该参会人的 SFU 推流权限并通知前端开麦；主持人点击「收回发言权」或「一键全员静音」后，SFU 服务端立刻撤回推流权限并关麦。
3. **画面聚焦与共享锁定**：正式会议默认仅主持人/协办人允许屏幕共享；主持人可锁定主讲画面或共享画面，确保所有参会端（尤其手机浏览器）稳定看到同一核心材料。
4. **会场安全开关**：主持人可随时「锁定会议」（禁止新入场）、「移出并吊销本场资格」、「一键结束全体会议」（强制销毁 SFU 房间并清理所有参会端媒体与会话）。

## 非目标

- 不做复杂分组讨论室（breakout rooms）；不做弹幕/自由匿名公屏刷屏（正式会议会中文字区默认仅支持“向主持人提问/提交书面意见”，由主持人决定是否公开回复）。

## 独立验收标准

- [x] 外部参会人加入正式会议后默认为只听态，尝试直接开麦或绕过 UI 发推流请求均在 SFU 侧被拒（隔离真实 LiveKit）。
- [ ] 举手队列按时间排序展示实名；主持人允许发言后，参会人可正常语音发言；主持人收回发言权或点「全员静音」后，该参会人推流在 2 秒内被服务端强制掐断。
- [ ] 外部参会人无法抢占屏幕共享；主持人开启共享后，桌面与手机浏览器均自动聚焦共享流。
- [ ] 主持人点击「结束全体会议」后，所有原生 APP 与外部浏览器参会端在 3 秒内退出房间并释放本机设备占用。
- [ ] 覆盖权鉴边界（普通参会人调用主持人控制接口一律返回 `403`）的集成测试 + 3 端以上真实联测通过。

**依赖**：`07`、`08`。  
**验证方式**：后端/SFU 权鉴正反例测试 + 多端（原生主持人 + 桌面/手机外部浏览器）真实实测。
