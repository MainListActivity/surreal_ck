# 全场景保密协同与会议规划（PRD）

> 更新时间：2026-11-25  
> 核对基线：`surreal_ck` `origin/main`（PR `#301`、`069-native-meeting.surql`、`native-client/`、`external-collaborator-portal`）及 `docs/design/collaboration-client-v2/`  
> 驱动来源：种子律所真实反馈——律所不仅需要日常保密办公开会，在破产等案件流程中还必须召开**债权人会议**；案件数据与会议内容高度保密，无法在腾讯会议、飞书等第三方公有平台完成。

## 1. 背景与当前规划缺口

当前仓库虽已在 `main` 落了 `069-native-meeting.surql`、`native-call`、`native-client` 与 `external-collaborator-portal`，但规划文档（`TODOS.md` / `EXECUTION_PATH.md`）尚未把协同与会议纳入主线，且现有实现存在以下关键缺口：

1. **只支持工作区内部成员，不支持外部人员参会**：`069-native-meeting.surql` 强依赖工作区 `record<user>`，无法接纳无需注册企业账号的外部访客、债权人、审计或法院观察员。
2. **强绑定原生客户端，缺免下载浏览器参会端**：外部人员（尤其是数十至数百名债权人、临时对接的客户）不可能为了开一次会去下载安装桌面客户端或注册账号；内部同事在临时设备上也需要 Web 端互通。
3. **媒体拓扑无法覆盖大规模会议与复杂网络**：现有 `native-call` 为纯 P2P Mesh 且无内置 STUN/TURN 凭据（需用户手填），公网跨网未验证；一旦超过 6–8 人或手机弱网参会，P2P Mesh 必然过载崩溃。
4. **缺少两种会议模式的差异化秩序与留痕能力**：日常办公会议追求随开随用、自由协作；受控外部正式会议（如债权人会议）要求实名名册核验、单活防转发、主持人强控静音/举手发言、会中表决/异议与签到结果自动回写工作簿。
5. **协同 APP 仍停留在“工程验收工具”形态且发布链未闭环**：`collaboration-client-v2` 指出的 8 项 UX 硬伤未落地；macOS 签名公证、更新公钥/feed、桌面媒体运行时供应链与原生文件接收验收尚未收口。

## 2. 平台通用抽象红线

遵循仓库 `TODOS.md` / `CONTEXT.md` 红线：**平台代码、数据库 schema、API 与系统提示不得出现法律或破产硬编码词汇**。

- 平台层只建模通用能力：**日常办公会议**、**受控外部正式会议**、**外部主体名册核验**、**议程与表决**、**签到与工作簿回写**。
- “债权人会议”“债权人名册”“管理人”“表决项模板”等行业术语、字段映射与话术统一由 `workbook_template` 模板包数据注入。

## 3. 全场景矩阵（必须全部覆盖）

| 场景维度 | 模式 A：日常办公会议（内部 / 轻量外部访客） | 模式 B：受控外部正式会议（如债权人会议 / 评审听证） |
| --- | --- | --- |
| **参会规模** | 2–12 人 | 10–300+ 人（宣讲 + 指定发言 + 全体表决） |
| **发起入口** | 协同 APP「会议」页、聊天会话一键拉会、Web 工作区顶栏 | 关联工作簿内发起，绑定外部主体名册与会议议程 |
| **内部成员入会** | 协同 APP 或 Web 浏览器直入，沿用当前 OIDC 工作区身份 | 同左，自动具备主持人 / 协办人权限 |
| **外部人员是否下载客户端** | **免下载**：桌面/手机浏览器直接入会（微信内置浏览器给出跳转系统浏览器引导）；已装 APP 亦可唤起 | **强制支持免下载浏览器直入**，兼容手机 4G/5G 与低配电脑，不强制安装客户端 |
| **外部人员是否注册账号** | **免注册**：一次性/限时访客链接 + 可选会议密码，填展示名进入等候室，主持人点放行 | **免注册，但必须名册实名核验**：个人专属参会链接 + 访问码，映射名册主体；**严禁创建工作区 `user` 记录或下发 DB 凭证** |
| **防转发与冒名** | 主持人可锁定会议、踢出访客并禁止重入、随时撤销访客链接 | 个人令牌**单活互踢**（同令牌后入踢前或拒并发）、主持人可单人吊销令牌立即踢出 |
| **跨网络与媒体承载** | 2–6 人支持 P2P + 托管短期 STUN/TURN（零手工配置）；超人数或穿透失败切换私有 SFU | 默认走**自托管私有 SFU**（数据不经过第三方公有会议云），仅下发主讲人/共享流，移动端支持纯音频省流 |
| **会中秩序控制** | 自由开关麦/摄像头、举手、共享窗口/全屏（防无限嵌套）、聊天与显式确认文件传输 | 默认全员静音且**锁定禁止自行解除**、举手申请发言→主持人点名开麦/收回发言权、锁定共享源、等候室批量/逐一放行、结束全体会议 |
| **保密与合规留痕** | 不默认云端录制；访客会话结束立即失效；不暴露工作区成员目录与业务表 | 自动生成**签到名册（入会/离会时间戳、核验主体、缺席标注）**、**表决统计与个人回执 PDF**，原子写回关联工作簿；若开启录制须全员红标提示 + 显式知情确认 |
| **异常与降级** | 断网自动重连保留会话与设备态；APP 支持最小化迷你条；权限被拒不死循环弹窗 | 手机切后台/来电重连保持签到连续性；低带宽自动降为纯音频；不支持 WebRTC 的老旧/内置浏览器展示清晰中文引导 |

## 4. 非目标（本期明确不做）

- 不接入腾讯会议、飞书、Zoom、声网等第三方公有会议 SaaS 云媒体服务（违背保密前提）。
- 不为外部参会人员创建企业 OIDC 长期账号，不开放外部人员浏览工作区其他工作簿或通讯录。
- 不做公网匿名免审核会议室（所有外部参会必须经过等候室放行或名册令牌核验）。
- 不做 AI 实时自动会议总结上传第三方大模型（涉及保密案件音频/字幕，后续若需必须单独评估合规边界）。

## 5. 任务拆分与依赖顺序

所有任务拆为与公司系统粒度一致的独立可验证单元，按依赖分 4 个波次推进：

- **波次 1（架构锁盘 + 协同 APP 去“验收工具感”）**：`01`（ADR）→ 并行 `02`（壳层与文案 v2）、`03`（消息/文件/会前检查 v2）、`04`（托管短时 TURN 与跨网实测）
- **波次 2（免下载 Web 参会 + 日常外部访客）**：`05`（Web 会议端与原生互通）→ `06`（外部访客免注册入会与等候室）
- **波次 3（私有 SFU + 受控外部正式会议闭环）**：`07`（私有 SFU 媒体平面）→ `08`（名册核验正式会议）→ `09`（主持人秩序强控）→ `10`（会中表决/异议与签到回写工作簿）
- **波次 4（签名分发 + 全场景生产验收）**：`11`（原生包签名/更新供应链）→ `12`（端到端压测与种子律所试运行验收）
