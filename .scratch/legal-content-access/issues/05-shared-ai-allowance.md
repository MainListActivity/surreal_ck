# 05 — 工作区共享 AI 额度闭环

**What to build:** 同一工作区的成员使用现有 AI 动作时共享可解释的额度；执行前看到预计或最高消耗，成功后结算，失败或未交付结果时释放预留。

**Repository:** surreal_ck

## Acceptance criteria

- [ ] 用现有一个可独立演示的 AI 动作贯穿版本化动作费率、套餐周期桶、原子预留、结算、释放和客户余额展示；不按成员分配额度，不向用户暴露 token 计价。
- [ ] 所有需计量的入口在调用模型或外部付费服务前经过统一门禁；尚未接入计量的收费路径保持不可用，不能用别的 Router 模式绕过。
- [ ] 预留绑定工作区、actor、channel、动作、费率修订与幂等键；并发余额不为负，重试不重复扣款，结算不能超过执行前已披露的上限。
- [ ] 按最早到期及既定同到期优先规则消费独立桶；失败返还原桶，原桶已到期时只记冲销，不恢复已过期可用余额。
- [ ] 预留有有限执行窗口及失联回收机制；取消、服务重启、部分交付和跨周期结算均有确定规则，产生可用部分成果时只按预先披露的档位结算。
- [ ] 客户能看到可用、预留、暂停和已过期余额及消费记录，50%/80%/100% 提示不重复轰炸；余额耗尽拒绝新收费动作，仍可查看自己的资料与合法历史成果。
- [ ] 普通内容检索、阅读、引用打开以及不调用生成模型的产品操作不消耗 AI 额度；余额不能替代内容或功能授权。
- [ ] 真实持久化测试覆盖并发扣款、幂等重试、模型失败、进程中断、桶到期、工作区隔离和未授权成员；费率与额度使用明确测试版本，不固化未经确认的生产数值。

## 范围与交接

本轮接通真人交互及共同账本。购买加量包的支付接入、机器通道预算产品化和正式价格实验不在此票。

遵守本簇已确认的产品规则、授权边界与发布门槛。完成时在 Comments 记录实现范围、验证命令与结果、未解决限制和下游交接；只更新本票完成状态，不自动关闭或修改产品设计父票。
