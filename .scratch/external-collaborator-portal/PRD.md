# 外部协作者门户 v2

- **日期**：2026-11-20
- **前置**：[债权人令牌提交窄入口 ADR](../../docs/adr/creditor-token-submit.md)、[11.1 债权对账数据模型](../../docs/claims-reconciliation/data-model.md)、[直连 ADR](../../docs/adr/frontend-direct-connect.md)
- **现状基线**：`server/src/routes/claims-portal.ts`、`server/src/claims-portal/`、`web/src/screens/ClaimsPortalScreen.svelte`、`web/src/components/ClaimsTokenDialog.svelte`、`ClaimsReconcileDialog.svelte`

## 问题陈述

破产案件里，管理人团队要和大量**没有账号的外部方**往来：几十到上千个债权人、债权人委员会成员、法院承办人，偶尔还有审计、评估机构。目前这些往来主要靠 Excel、邮件和微信群，因此有三个后果：

1. 管理人要把同样的状态逐个回复给债权人（「收到没有」「审到哪一步了」「还缺什么」）。
2. 补正要求和回复散在聊天记录里，事后无法证明是谁、在什么时候、要求了什么。
3. 向债委会或法院汇报进度时，要另做一份 Excel 摘要，数据一导出就过时。

v1 债权人门户（ADR `creditor-token-submit`）已经实现令牌打开、填写草稿、提交、上传附件，以及基于 `claim_supplement` 的补正往返。它还缺这些：

- **债权人看不到进度和结论**：页面只有申报内容和补正记录，看不到「已受理 / 审查中 / 已确认金额 / 有异议」这类状态，也看不到管理人发布的审查结论。
- **管理人缺发放与催办视图**：令牌只能逐个生成、复制，没有批量发放，也没有按「未打开 / 未提交 / 待补正 / 超期」筛选的催办清单。
- **只有债权人一种外部角色**：债委会和法院想看进度，只能由管理人导出发送。
- **审查结论没有对外发布的动作**：`managerNote` 是内部笔记，没有「对债权人公开的结论」，也没有供债权人提出异议的入口。

## 目标

1. 债权人自己就能查到进度、补正要求和审查结论，管理人收到的「问进度」类咨询明显减少。
2. 补正、结论、异议的每一次往来都留在案件库里，可以导出作为程序材料。
3. 债委会和法院能通过只读链接看到**聚合**进度，管理人不用再手工做汇总表。
4. 不扩大身份面：外部方仍然不拿 IdP 账号、不拿 workspace scope、不直连 SurrealDB。

## 非目标

- 系统不代发邮件或短信。沿用 ADR 的约定：只生成链接，由管理人自行转发。是否接入通知渠道单独决策，见「待决事项」。
- 不支持未知债权人公开自助报名（ADR §4 不变）。
- 不做真人实名核验（支付宝、微信等），留到下期。
- 外部方不能查看其他债权人的明细、企业账面、利息快照或对账并排视图。
- 不做外部方之间的聊天或群组。
- 不把外部方加为工作区成员。实体表权限只到成员级、没有行级细分，所以把外部方拉进工作区等于把全案数据给了对方。

## 方案概述

继续沿用 v1 的思路：每类外部角色各有一组**带令牌的窄入口路由**，由服务端受控会话读写案件库中限定的几张表。本期在 v1 之上新增三块能力：

| 模块 | 面向 | 新增内容 |
| --- | --- | --- |
| A. 债权人进度与结论 | 债权人 | 状态时间线、管理人发布的审查结论、异议提交、补正截止时间 |
| B. 发放与催办 | 管理人（已登录，直连） | 批量生成令牌、按状态筛选的催办清单、补正模板、导出往来记录 |
| C. 只读进度链接 | 债委会成员、法院承办人 | 案件级聚合看板（数量、金额分布、进度），不含任何个人明细 |

模块 C 是对「后端不做业务代理」原则的**第二个窄例外**，需要先修订 ADR（见「架构与安全」）。

## 用户故事

### 债权人

1. 作为债权人，我希望打开链接后先看到我的申报处在哪一步，这样不用打电话问。
2. 作为债权人，我希望看到一条带时间的状态时间线（已提交、已受理、要求补正、审查中、已出结论、已确认），这样我知道每一步发生在什么时候。
3. 作为债权人，我希望补正要求写明需要什么、截止到哪天，这样我能一次补齐。
4. 作为债权人，我希望补正时可以同时上传新附件并说明，这样补正内容不会散落。
5. 作为债权人，我希望看到管理人正式发布的审查结论：确认金额、未确认部分、理由。这样我知道结果。
6. 作为债权人，我希望在异议期内对结论提出异议，写明理由并附材料，这样我的异议有据可查。
7. 作为债权人，我希望异议期结束后页面明确显示「异议期已届满」，而不是按钮静默失效。
8. 作为债权人，我希望能下载一份「我的申报与往来记录」PDF 留存。

### 管理人

9. 作为管理人，我希望从名册里勾选多位债权人批量生成链接，并导出成「名称、识别码、链接」表格，这样可以用自己的渠道群发。
10. 作为管理人，我希望批量生成时，明文链接只在这一次导出里出现，以后不能再看。这与 v1 单个令牌的规则一致。
11. 作为管理人，我希望按「未打开 / 已打开未提交 / 已提交 / 待补正 / 补正超期 / 有异议」筛选债权人，这样可以有针对性地催办。
12. 作为管理人，我希望用模板发起补正要求（缺合同、缺对账单、利息起算日不明等），并设置截止日期。
13. 作为管理人，我希望把审查结论分成「内部笔记」和「对外结论」两部分，只有点了「发布」，对外结论才对债权人可见。
14. 作为管理人，我希望已发布的结论不能原地修改，只能发布新版本，债权人能看到版本历史。这样对外表态可追溯。
15. 作为管理人，我希望设置案件的异议期截止时间，到期后系统自动拒绝新的异议。
16. 作为管理人，我希望导出某位或全部债权人的往来记录（补正、回复、结论版本、异议），作为程序材料。
17. 作为管理人，我希望能随时作废某个外部链接，作废后立即失效。

### 债委会成员与法院承办人

18. 作为债委会成员，我希望通过管理人给的只读链接看到申报总数、已审查数、确认金额合计和各类债权占比，这样开会前心里有数。
19. 作为法院承办人，我希望看到按周的进度变化和待处理异议数量，这样可以督促进度。
20. 作为只读访问者，我希望页面标明数据更新时间和统计口径，这样我知道数字是否新鲜。
21. 作为管理人，我希望给每位只读访问者单独发链接、设有效期，并能看到每个链接最近一次访问的时间。

## 功能需求

### A. 债权人进度与结论

- **A1 状态模型**：在现有 `claim_submission.status`（`draft | submitted | needs_info | closed`）的基础上增加对外进度阶段：`submitted → accepted → needs_info → under_review → decision_published → objected → final`。状态迁移由管理人动作或系统规则触发，每次迁移追加一条**进度事件**（时间、阶段、由谁触发）；对债权人只显示「管理人」，不显示具体成员。
- **A2 补正要求**：`claim_supplement` 中 `direction = "manager_request"` 的记录增加 `due_at` 和 `template_key`（可为空）。债权人回复时可以关联同一次补正上传的附件。
- **A3 对外结论**：新增**结论版本**记录，包括确认本金、确认利息、确认违约金、未确认金额、对外理由、版本号、发布时间、发布人。只追加，不更新。`managerNote` 仍是内部字段，门户响应里不出现（v1 已删除，保持这一点）。
- **A4 异议**：新增**异议**记录，包含关联的结论版本、理由（1–4000 字）、附件、提交时间、处理状态（`open | answered | withdrawn`）。案件级设置 `objection_deadline`；过期后返回 409，页面显示「异议期已届满」。
- **A5 留存下载**：服务端生成本人申报摘要及往来记录的 PDF，只包含本人数据。
- **A6 加固 v1**：门户响应中的附件元数据不再返回 `storageKey`（当前 `serializeAttachment` 会把它返回给债权人，而它包含 `workspaceDb`），改用不透明的附件 id。

### B. 发放与催办（管理人侧）

- **B1 批量签发**：新增 `POST /api/workspaces/:slug/claims-portal/tokens:batch`，只允许 admin，复用 v1 的 `assertAdminScope`。单次上限 500 条。对每位债权人吊销旧的 active 令牌并签发新令牌，返回的明文只用于本次 CSV 下载，不入库、不进日志。
- **B2 催办清单**：浏览器直连读取令牌状态、申报状态、补正截止时间和异议，在债权工作簿内提供筛选视图。这部分是**直连查询**，不新增后端读接口。v1 管理人列表接口保持不变。
- **B3 补正模板**：模板随 `bankruptcy-claims` 模板包分发，管理员可以修改。
- **B4 往来导出**：在浏览器里由直连数据生成 CSV 或 PDF，范围是单人或全部。
- **B5 作废**：作废后，所有带该令牌的会话在下一次请求时失效。v1 的 `assertTokenMatchesSession` 已逐次回查令牌状态，需要用测试覆盖这一点。

### C. 只读进度链接

- **C1 查看令牌**：新增**查看令牌**，与债权人令牌分开存放。包含：令牌哈希、访问者标签（如「债委会·张某」，只给管理人看）、角色（`committee | court`）、到期时间、状态、最近访问时间、访问次数。明文只显示一次，和 v1 一样只存哈希。
- **C2 打开方式**：打开时要输入管理人另行告知的访问码，错误时统一提示，并沿用 v1 的限速常量。会话有效期比债权人短，暂定 2 小时。
- **C3 聚合看板**：只返回聚合值：申报数、各阶段数量、申报金额与确认金额合计、债权类型分布、按周进度、待处理异议数。**任何一个分组的人数少于 3 时，该分组合并为「其他」**，防止从聚合结果反推出个人。不返回名称、识别码、附件或单笔金额。
- **C4 角色差异**：`court` 比 `committee` 多一项「待处理异议数与最长等待天数」。字段白名单写在代码常量里，并用测试锁定。
- **C5 口径标注**：响应里带 `generated_at` 和口径版本号，页面显示「数据截至 …」。

## 架构与安全

- **ADR 修订是前置条件**：模块 A 是 v1 债权人入口的自然延伸，可以在现有 ADR 范围内完成。模块 C 新增了一类外部主体和一个只读聚合入口，需要先在 `docs/adr/` 写修订或新 ADR，经经理批准后才能开工。修订要写明：只返回聚合结果、有字段白名单、有小分组合并规则，不提供通用查询能力。
- **写入身份**：沿用 v1 的受控服务端会话，只操作本案件库中列出的表。不引入 service JWT，也不让浏览器持有任何数据库凭证。
- **Schema**：新增的表和字段按序号追加到 `shared/sql/workspace-template/`。动手前先查 origin/main 上最新的迁移号。PERMISSIONS 中，进度事件、结论版本、异议对 admin 可读写，对 participant 只读；外部入口通过服务端会话写入。
- **配额**：新增表计入 workspace 原生配额。批量签发前要预检 record 余量，超额时整批拒绝，并给出中文提示。
- **审计**：签发、作废、发布结论、处理异议、查看令牌被访问，都要写最小审计记录（谁、何时、对象 id），不记录正文。
- **限速与枚举防护**：门户各路由按令牌加 IP 限速。令牌不存在、已作废、已过期时，响应都和「输错访问码」一样，不暴露令牌状态。

## 分期

| 阶段 | 内容 | 完成标准 |
| --- | --- | --- |
| P0 | A1、A2、A3、A6、B1、B2、B5 | 债权人能看到进度和已发布结论；管理人能批量签发并按状态催办 |
| P1 | A4、A5、B3、B4 | 异议闭环可用；往来记录可导出 |
| P2 | C1–C5（以 ADR 修订通过为前提） | 债委会和法院链接上线，聚合口径通过测试锁定 |

## 验收标准

1. 债权人在门户里能看到时间线和最新发布的结论；管理人的内部笔记在任何门户响应中都不出现（用响应快照测试断言）。
2. 已发布的结论版本没有更新路径；改结论会生成新版本，旧版本仍可见。
3. 异议期过后提交异议返回 409，页面显示中文提示。
4. 批量签发 500 条只需一次请求；导出文件之外，日志、数据库、响应缓存里都没有明文令牌。
5. 令牌作废后，带旧 cookie 的下一个请求返回统一的失败响应。
6. 门户响应里不再出现 `storageKey` 和 `workspaceDb`。
7. 只读看板中，人数少于 3 的分组被合并；字段白名单之外的字段由测试拦截。
8. fork 集成测试覆盖：迁移链连续、PERMISSIONS 按 admin 和 participant 区分、配额超额时整批拒绝。
9. 用 `web/` 的真实页面走通一遍：管理人批量签发 → 债权人打开、提交 → 管理人要求补正 → 债权人补正 → 管理人发布结论 → 债权人提出异议 → 只读链接看到聚合数字变化。

## 指标

- 每个案件中，债权人从打开链接到提交的转化率，以及从首次补正到补齐的平均天数。
- 已发布结论中被异议的比例，以及异议的平均处理时长。
- 只读链接的周活跃访问数。
- 用于对比的定性指标：试点管理人反馈的进度咨询次数是否下降，通过访谈采集。系统不读取外部聊天。

## 待决事项

1. **通知渠道**：是否为补正和结论发布接入短信或邮件。这会改变 ADR「系统不代发」的约定，涉及费用和合规，需要老板决定。
2. **只读角色范围**：除了债委会和法院，是否把审计、评估机构作为「可上传材料的外部机构」纳入本期。建议推到 v3。
3. **异议期规则**：是全案统一一个截止日，还是按每位债权人的结论发布时间加 N 天计算。需要律师顾问确认程序依据。
4. **数据保留**：案件结案后，外部链接和往来记录保留多久，归档后是否允许下载。
