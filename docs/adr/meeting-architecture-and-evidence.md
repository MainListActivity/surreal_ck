# ADR: 保密会议的双模式、外部身份与存证

- **Status**: Proposed
- **Date**: 2026-11-26
- **Scope**: M-01；约束服务端、工作区 schema、Web 与原生会议端的后续实现。本 ADR 不交付业务代码、迁移或部署。

## Context

现有 `069-native-meeting.surql` 为已获邀请的工作区成员提供会议房间和 P2P 信令。无账号访客不能复用成员身份；大型会议的带宽、主持控制与全程存证也不能由成员 Mesh 或客户端时间承担。日常会议和受控外部会议共用跨端协议，但准入、媒体与留存策略不同。

## Decision

### 1. 控制面与媒体拓扑

| 会议模式 | 准入 | 媒体与录制 |
| --- | --- | --- |
| 日常会议 | 工作区内有效成员；主持人显式开启后，访客经等候室放行 | 目标为 2–6 人优先 WebRTC Mesh，先试直连，失败在新 ICE 轮次用公司受控 TURN。第 7 人获准前、短期 TURN 仍无法建立媒体或主持人开启录制时，目标是全房切私有 SFU。默认不录制。当前上限和入口见 §6。 |
| 受控外部会议 | 有效内部成员按会议角色进入；外部人员凭个人令牌和访问码完成名册核验 | 不论人数只走私有 SFU；默认全程存证、默认锁麦；只订阅主讲/当前发言、共享及必要音频，不做全员视频网格。 |

Bun origin 是新协议唯一的会议准入、拓扑版本、角色、踢出和媒体授权控制面。前端 Worker 复用既有反代入口，仅转发；TURN 只做中继；SFU 执行授权并回报媒体事件，不拥有名册、工作簿或业务数据库密钥。内部成员仍用 OIDC 工作区身份，普通业务读写和 LIVE 仍经 SurrealDB 直连；会议 API 只暴露固定会议操作，不提供任意查询、工作簿 CRUD 或 LIVE 代理。状态和权威事件按工作区 database 隔离。成员业务写入须走调用者会话，外部会话由服务端按已核验的工作区、会议及主体用受限会话执行预定义操作。邀请中的工作区和房间定位信息只用于服务端查找与核验。表决/签到回写只执行经管理员预先绑定的模板字段映射，由原生配额和事务拒绝越界/超限。Root 只用于明确的维护和控制面职责，名册会议的身份和验收见 §6。

M-04 仅向获准的内部成员/会议会话发放会话绑定、TTL 不超过 15 分钟的 ICE 凭据；重连时按需续签。TURN 禁止转发至非授权目标、私网与回环，不使用公共 TURN 或客户端静态密码。切换拓扑由服务端增加房间媒体代际，统一通知客户端关闭旧连接并重新协商；同一房间不得因各端自行回退而分裂。切换失败则保持已验证安全的旧拓扑及原人数上限，拒绝引发切换的新增入场或录制请求；正式会议、需要强控或已启录的房间不得回退 Mesh、取消录制后静默继续，SFU 或录制失效时显式暂停媒体准入/存证并告警。依赖 SFU 的准入和录制须在私有媒体面及相关门禁就绪后开放。

### 2. 私有 SFU 选型、部署与容量

选用**自托管 LiveKit**：复用标准 WebRTC、Web/移动/原生 SDK 接入能力、服务端参与者管理和轨道发布权限，以及独立的 Track Egress。相较 mediasoup，少自行组装房间信令、客户端互通和录制桥接；代价是接受 LiveKit 协议与部署约束，仍须在 M-07 实测现有 Rust 原生端及 Android 适配，不把 SDK 可用性当成互通结论。

**2026-11-27 负责人决策修订（同机首期部署，后续横向拆出）**：首期不单开独立媒体主机，直接在现有主/数据主机（`data.maplayer.top` / `vps-data`，2 vCPU / 11 GiB RAM）上同机部署单实例 LiveKit SFU、本机私网 Redis 与 Track Egress，待业务规模和带宽增长后再迁出至独立私有媒体主机。同机部署下仍保持最小暴露面与控制面边界：LiveKit 管理 API 与信令上游仅监听主机私网地址（`10.0.0.112:7880`，公网不可达），仅 Bun 本机访问；LiveKit webhook 仅走本机回环（`http://127.0.0.1:8080/internal/meeting/sfu/livekit-webhook`），不经公网反代暴露；客户端 SFU 信令复用 `data.maplayer.top:443` 现有 Caddy 入口，仅放行 `GET /api/meeting/sfu/signal/rtc` 与 `/rtc/validate`（屏蔽 `/twirp/*`，不记录查询参数），禁止直连原始信令地址；媒体 UDP 端口从既有已放行区间拆分（`49350–49359/udp`，coTURN 缩为 `49160–49349/udp`）。每次连接/重连除 SFU JWT 外还须检查当前会议会话代际。短时 JWT 只授权指定房间、参与者及允许的订阅/发布类型（只听者不授权发布），不把短 TTL 或踢出后原 JWT 自动失效当成撤销机制。Track Egress 与离线合成使用隔离系统用户与暂存组权限（不跑无头浏览器实时合成）；开放的新服务、端口与路由边界均经授权并登记至 `surreal-ck-operations` 公司资产清单，不引入第二个控制面或公有会议云。

独立媒体主机目标基线为 **30 人/房间、每实例共 30 活跃连接**（以至少 30 个连接持续 15 分钟验证，并在测试环境对超过 30 个连接加测录制；工程预算假设主讲 1.5 Mb/s、共享 2 Mb/s、音频合计 0.1 Mb/s，带 25% 协议/重传余量，30 个接收端最坏同订阅约 135 Mb/s 出网，300 人约 1.35 Gb/s 不在首期承诺内）。**同机部署容量收紧**：由于 `vps-data` 仅有 2 vCPU / 11 GiB RAM 且与生产 SurrealDB、Bun API 共用 CPU、内存、磁盘 IO 与出网带宽，首期将生产席位上限保守下调至 `MEETING_SFU_MAX_SEATS=15`（LiveKit `max_participants: 15`），并在该主机记录 CPU、内存、网络、录制负载与同期 Hono/SurrealDB 延迟；人数或资源预算先触顶即停止新增入会。带宽不足优先降低视频层、暂停非必要视频或降为纯音频；单实例故障显式提示重连/暂停，不回落到公有媒体或无审计通道。更高容量须迁出独立媒体主机并另作压测与部署评审。

### 3. 外部认证、生命周期与防枚举

两类入口均只授予当次会议权限，不走 OIDC、不注册企业账号、不创建工作区 `user`、不签发 SurrealDB 凭证，不可读通讯录、历史消息、工作簿或其他会议。会议内部只投影当前角色所需信息；名册、等候室和完整审计不向普通参会人公开。

| 规则 | 日常访客 | 名册参会主体 |
| --- | --- | --- |
| 签发与认证 | 默认关闭；主持人生成限时链接，可加 6 位访问码。访客输入展示名、访问码（如配置）后仅获等待会话；主持放行才升级。拒绝、锁房或过期不授予任何存量媒体权限。 | 工作区管理员按工作簿名册批量签发个人链接和独立访问码，每批最多 500 条，原生配额预检并事务提交。服务端校验令牌与访问码两项、绑定名册 ID；展示实名来自绑定行，不接受自报实名替换。需存证时知情确认先于媒体授权。 |
| 链接生命周期 | 默认 2 小时，且不晚于会议关闭或有效期；主持人可轮换/关闭，旧代际及其已签发会话一起失效。 | 默认签发起 7 日，且不晚于会议结束；一次性导出明文（CSV 防公式注入），可单独补发/吊销，旧令牌和会话同时失效。 |
| 单活、重连与驱逐 | 共享链接不是身份；同一访客会话仅允许一个当前连接代际，重连替换旧连接，踢出撤销并禁止该会话重入。禁止持同一链接绕过踢出再排队时，轮换入口并重新核验；不能把未实名访客的 cookie/IP 当作可跨设备识别自然人的凭证。 | 按工作区 + 会议 + 名册主体原子维护唯一活动租约，不按浏览器或令牌明文。新设备完整核验后默认替换旧会话，或按房间配置拒绝并发；重连使用当前有效会话。补发、踢出、吊销、互踢均记录服务端 UTC 及最小操作者/对象 ID。 |

沿用外部门户的服务端受控会话模式。链接令牌用加密安全随机数（至少 256 bit），数据库只存带服务端密钥的校验摘要；访问码只存加盐、带服务端保密材料的校验值；比较避免时序泄漏。不把令牌、访问码、原始 SDP 或凭据写日志、分析事件或 Referer；入页后清除地址栏令牌，不加载第三方跟踪。浏览器使用作用域限于会议入口的 `Secure`、`HttpOnly` cookie，日常访客用 `SameSite=Lax`，名册用 `SameSite=Strict`。变更请求须核验 Origin 并落实 CSRF 防护。后续接入的原生端须使用同等短期、仅限该场会议的会话。会话默认最长 2 小时，等待态最长 15 分钟；续期必须再次核验当前代际与准入状态，且不得超过链接或会议有效期。

每来源 IP（仅信任配置的反代）每 15 分钟最多核验 30 次。每候选链接摘要或名册令牌摘要在 15 分钟内失败 5 次即锁 30 分钟。不存在的令牌也走同类受限路径，限速计数设 TTL 并受来源总额度约束。无效、过期、关闭、已吊销及错码使用统一拒绝响应，不回显名册数据。限流通常返回 `429`，启用公开入口防护时，名册核验把应用层限流折叠为相同拒绝响应。等候室只允许读取自身等待状态，绝不下发成员列表、聊天、SDP 或 ICE/SFU 凭据。

### 4. 跨端信令、设备与升级

- 新协议以 TLS 上的 HTTPS 命令和版本化快照为基础，目标支持 WSS 有序增量事件。房间状态为开放/结束，参会状态为待核验、等候、获准、重连中或终止。关联键为工作区、房间、参会主体、入会实例/代际及媒体轮次；重连先验证会话，再按版本补事件或重取快照，拒绝过期代际、跨房间和重复写入。客户端不凭本地时间认定租约。
- Mesh 使用 WebRTC SDP offer/answer 与 ICE（兼容旧端完整 ICE 收集后交换 SDP 的轮次）；同轮次的发送/接收双方及权限由服务端绑定。SFU 使用 LiveKit 媒体协商，主持命令、成员、聊天和会议结束仍由统一会议协议裁决；聊天只对获准同场端可见，不转发历史工作区消息。macOS、Windows、Android 和 Web 必须验证共同协商的 SDP/编解码能力以及音频、视频、共享、文本、进出与散会；不将厂商 SDK 专有信令当成业务协议。
- 授权是服务端状态，不是 UI 状态。踢出、吊销、替换或散会先原子撤销代际，后续命令/重连返回 `401/403`，主动关闭旧信令并收回媒体：SFU 撤销发布/订阅、移除参与者或销毁房间；受支持的 Mesh 端收到撤销即关闭对应连接，失去控制通道时按短租约关闭，不等 TURN 凭据过期，按 M-06 验证 3 秒断流。Mesh 无法对两个串通或不受控端实施服务器级断流；要求独立服务端强制执行时用 SFU，不把 UI 静音、ICE TTL 或已收到的内容当作可远程收回。正式会议无自开麦权限，主持人授权/收回由 SFU 执行，收回后 2 秒内断推流，散会 3 秒内各支持端退出。
- 设备默认关闭；预检只在用户操作后临时取流且结束即释放。会中媒体开关须同时满足本地权限、用户选择及发布授权；网络切换只在原权限和用户选择仍有效时恢复，不擅自打开摄像头、麦克风或重启屏幕共享。遇终止、离会、关页或授权失效立即关闭 PeerConnection、停止所有轨道并释放原生设备；离会信令尽力发送，服务端租约负责异常退出收敛。

名册会议的锁房、举手队列、临时发言权与画面焦点随 SFU 房间生命周期结束，不跨房间恢复；资格吊销和会议结束仍沿用名册数据的持久状态。外部席位的入会与续期凭据始终为只听，临时授权由服务端对当前 SFU 席位授予，仅开放麦克风。获准者在本地操作后才开启麦克风。锁房阻止新席位准入，不撤销已有席位。屏幕共享开放给主持人及其显式授权的同场协办人。协办授权仅允许共享屏幕，随房间销毁。自动焦点优先主持人共享，锁定时不跟随活跃发言者改变画面。

| 端 | 入会及降级边界 |
| --- | --- |
| macOS / Windows / Android 原生端 | 与 Web 同房互通是跨端验收目标，能力按设备、系统与客户端版本检测。首期试点外部名册核验统一走 Web，原生名册衔接由 M-08 后续验收。 |
| 桌面系统浏览器 | HTTPS 下的 Chrome、Edge、Firefox、Safari 做候选验收；设备允许时音视频、聊天及屏幕共享，按实际能力检测。 |
| 手机系统浏览器 | iOS Safari、Android Chrome 作为首期真机基线；支持免安装、触控、切网重连和纯音频；不承诺移动端发起屏幕共享。 |
| 微信/钉钉内置 WebView、老旧或受限浏览器 | 不出现白屏或反复授权，中文提示「点击右上角在系统浏览器打开」或复制链接继续；不将令牌交给第三方跳转服务。 |
| 无设备或权限拒绝 | 无摄像头降为纯音频；无麦克风降为只听，均不阻塞聊天或准许的表决；无可用播放能力时明确提示。 |

升级保留 [069](../../shared/sql/workspace-template/069-native-meeting.surql) 及旧 `meeting_v1`：现有入口 `fn::meeting_*` 依赖 `participant` 和活跃 `record<user>`，保留旧房、租约、邀请、SDP 轮次水位和 GC；V1 不承载外部身份、录制或强控，不访问 V2 房间，也不修改独立的 062 双人信令。M-05 通过兼容适配器先让 Web 和未升级原生端在内部 V1 房互通；新能力经协商只在 V2 房启用，使用独立版本化入口与状态，禁止绕过 V2 经 V1 加入、双写或静默降级。

后续只在 workspace 模板追加版本化迁移，增设通用会议参与者（成员引用或外部主体引用）、准入、事件及归档记录；不把外部 ID 填入旧 `record<user>`，不覆写 069、不搬迁正在进行的房间。既有工作区先迁移并验证能力探测、旧端/新端互通及跨库负例，再逐场开启 V2；回滚关闭新能力和新房入口，保留既有归档且不把已开 V2 房降级成无控制的 V1 房。平台代码、schema、API 与系统提示仅使用通用会议/名册/议程/存证名称；行业字段、角色称谓及话术只由 `workbook_template` 数据提供。

### 5. 受控录制与不可变存证

日常会议默认不录制，不启动 egress、不落盘音视频。主持人手动开启时先告知并点亮全端常驻红标，再开启 SFU 采集；晚加入者入场前仍须被告知。正式会议默认全程存证，预先明确采集范围，每位内外参会人入场前必须主动勾选确认；记录告知版本、确认主体和服务端 UTC。仅在红标和采集均就绪时准许进入录制媒体，状态不明时不得无提示继续。端到端加密（E2EE）意味着 SFU 无法解开轨道；服务端存证录制与浏览器 E2EE 不能同时启用。存证采用传输加密和存储加密，不标称 E2EE；不得静默关闭已有 E2EE 来录制。未录制也不等于已经具备 E2EE。

1. **权威时间轴**：Bun 准入、核验、同意与会控事件，SFU 的加入/重连/离开/踢出/替换事件，以及 M-10 只追加账本的举手、授权/收麦、议题版本哈希、投票、异议与汇总，用同步的服务端 UTC 时间与同场事件顺序对齐，不信任设备时钟。签到快照关联 OIDC 主体或名册令牌哈希 ID，按主体去重、保留每段在线时间；网络/客户端信息按最小必要脱敏，不入库明文访问码、令牌或原始 SDP。表决按主体和议题版本幂等计票、由服务端截止时间裁决，个人回执仅含本人的记录。回写使用稳定键及事务，重试不重复插入。
2. **轻量采集**：私有 SFU 用 Track Egress 采集主讲/发言人视频、共享及发言音轨，实时加密写入隔离存储，不在生产库主机做无头浏览器实时合成/转码。会后由隔离作业按 UTC 映射生成带服务端 UTC 和会议号水印的 MP4、混音和分发言人音轨；签到 CSV/PDF、举手发言时间线和表决汇总共享时间轴，M-13 验证媒体与事件误差不超过 2 秒。
3. **访问与保留**：独立私有对象桶按工作区及会议隔离前缀，工作区级密钥包装每包/对象数据密钥进行信封加密；桶不开放公网直链。仅本工作区管理员经 Bun 校验授权和记录审计后获取短时、仅针对单个产物的签名下载入口；普通成员、访客和跨区管理员均拒绝。归档纳入工作区存储容量和显式保留策略，到期前通知管理员离线备份，不静默删除未归档证据。
4. **封存与校验**：先冻结音视频、账本快照、附件和可读摘要 PDF；不可变 Evidence Manifest JSON 记录会议元数据、签到和议题索引、每项产物相对路径、精确字节数和 SHA-256。根哈希是清单确定性 UTF-8 序列化字节的 SHA-256（32 字节，不把自身或后置 TSA 回执写回清单）；落入工作区只读归档索引。包附清单、产物及离线校验说明；以可信根哈希比对清单，逐项验长度/哈希，任意 1 字节篡改须失败。哈希证明相对可信根的完整性，不单独证明采集真实性或法律效力。
5. **可信时间戳扩展**：为 TSA 留供应商无关接口，仅出站 32 字节根摘要及最小协议元数据；不上传名单、业务正文、音视频或附件。回执单独保存并关联同一根摘要，离线验证回执与根摘要；首期用测试替身，不默认开通商业服务。

**不可变性的信任边界**：工作区事件和归档索引按只追加/只读设计，业务 API 无 UPDATE/DELETE，schema 对受 `PERMISSIONS` 约束的角色显式拒绝改删。但现有 `ac=admin` 是拥有 DDL/DML 的数据库 `Owner`，不能声称表级权限能挡住 Owner 或 root。权威账本与根锚点还须保存在工作区数据库 Owner 无法触及的私有存储信任域，以按序追加的凭据写入，在保留期禁止覆盖或删除；工作区索引是查询投影，独立校验从可信锚点取根，投影不一致则报错。M-10/M-13 在真实 fork 区分业务角色、直接 DB Owner 和运维权限，验证越权与投影篡改负例。若要求 Owner 即使通过 DDL 解除守卫也无法修改工作区投影，须先评审 fork 的强制不可变能力或变更角色/隔离方式；本 ADR 不变更成员直连与 DDL 权限。

**同机部署下的存证存储域边界说明**：将媒体服务同机部署在 `vps-data` 不改变工作区数据库与存证域之间的应用与操作系统隔离——`MEETING_EVIDENCE_DIR`（`/var/lib/surreal-ck/meeting-evidence`，`0700 ubuntu:ubuntu`）与 `MEETING_EVIDENCE_MASTER_KEY` 独立于 SurrealDB 数据目录、备份和工作区数据库凭据，且 Track Egress 以独立的非 `ubuntu` 系统用户（`meeting-egress`）运行，无权读取存证目录或密钥；因此**工作区 DB Owner（`ac=admin`）、普通成员与外部访客仍无法触及、覆盖或删除可信根与加密存证，投影篡改仍可被独立校验检出**。但在单台主机上无法对抗**宿主机 root/运维级权限**同时触及 SurrealDB 与本机存证目录，也不具备跨机物理容灾；若后续需要对抗宿主机 root 级篡改或实现物理不可变留存，须将存证域迁至独立只追加/WORM 对象存储或独立主机。

**M-13 验收口径**：在 schema 完整时，工作区会议账本和归档投影对所有角色拒绝直接 `UPDATE/DELETE`：普通角色由 `PERMISSIONS` 拦截，Owner/root 的直接 DML 由只读字段和事件守卫拦截。Owner/root 能通过 DDL 移除工作区守卫，因此对两者承诺的是篡改可检测，不是工作区数据不可变。独立核验不信任工作区投影或包内自报的根哈希；由独立存证域提供可信根，并报告缺失或不匹配的投影。工作区数据库权限不授予独立存证域的覆盖、删除或密钥权限。
