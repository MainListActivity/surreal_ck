## 一、现状为什么显得丑、难用

问题主要出在信息架构和文案，配色本身问题不大。

| # | 现象（代码位置） | 后果 |
| --- | --- | --- |
| 1 | 工程约束直接当界面文案：`不会生成示例联系人或聊天记录`、`不会模拟登录`、`已送出 · 无送达回执`、`尚未接入企业会话，无法开始真实会议`（`first_screen.rs`） | 用户读到的是测试说明，像一个验收工具而不是产品 |
| 2 | 会话栏顶部常驻两行状态（`identity.line()` + `session.line()`），列表区只有一个「直连会话」卡片（`lib.rs` conversation_list） | 最显眼的位置是状态说明，真正的会话列表被挤到下面 |
| 3 | 每个浅色页面顶部都有一条灰色横条：窄屏导航 + 窗口标题 + 隐私条 + 「断开并停止媒体」按钮（`lib.rs` 约 860 行） | 标题重复出现，「断开」这种危险操作常驻在首屏 |
| 4 | 气泡没有头像、姓名、时间，也不分组；对方消息用 `label()` 拼成「对方：…」 | 群聊里分不清谁说的，阅读节奏全靠气泡底色 |
| 5 | 点「会议」直接进深色舞台：6 个坞按钮 5 个禁用，下方再加两行灰字解释原因，右侧 4 个空槽 + 「暂无参会人」 | 没有进行中的会议时，整页都是禁用控件和解释 |
| 6 | 登录、工作区切换、成员目录、企业聊天连接全塞在「成员」页的 `identity_ui`（约 2000 行）里 | 登录是使用一切的前提，却藏在第三个标签页里 |
| 7 | 设置页和诊断页用通栏卡片堆叠，诊断页直接展开 P2P 连接码、STUN/TURN、媒体与文件调试面板 | 普通设置和开发者工具看起来同等重要 |
| 8 | 共享选择器 2×2 都是「尚未接入捕获」空槽，开始按钮永远禁用 | 共享是会议核心能力，却看不到选择流程 |

问题 1、2、5 主要靠文案和空状态就能改好，和视觉无关；问题 3、6、7 是信息架构需要调整。

## 二、改版原则

1. **四个模块，一层导航**：消息、会议、通讯录、设置。左侧 72px 图标栏，上方是工作区切换，下方是设置和头像。一个模块只做一件事。
2. **状态集中在一个地方**：网络状态和媒体占用只在标题栏右侧出现，平时什么都不显示。断网时出现「正在重连 / 已离线」胶囊，会议中出现红色「麦克风 · 摄像头」胶囊，点开可以单独停止或「停止全部媒体」。「断开并停止媒体」不再常驻首屏。
3. **诚实但不说教**：保留「已送出」不冒充「已读」、离线消息显示失败可重试、文件需对方确认才传输、共享需选源才可开始这些真实约束，但用户看到的是正常的产品文案（「等你确认后才会开始传输」「发送失败 · 重试」），不说明系统「不会做什么」。实现细节写进代码注释和本文档。
4. **会议先有入口，再有舞台**：会议模块默认是浅色首页（立即开会 / 输入会议号 / 进行中 / 最近结束），加入前统一经过「会前检查」，确认后才进深色舞台。舞台可以「返回消息」最小化成右下角迷你条，会议继续进行。
5. **开发者工具降级**：诊断放在设置底部的「开发者诊断」，默认只有一个按钮，点开才显示连接信息。

## 三、各场景设计要点

### 登录与选择工作区

启动后第一屏。三步：使用企业账号登录 → 在浏览器中完成（等待中可重新打开或取消）→ 选择工作区。说明登录在系统浏览器完成、应用拿不到密码，对应现有 PKCE / loopback 方案。

### 消息

- 会话栏：标题 + 新建（私聊 / 群聊 / 立即开会）、搜索、全部 / 未读 / 群聊。会话行包含头像、在线点、时间、最后一条消息、草稿（红字「[草稿]」）、置顶和免打扰图标、未读数（免打扰的会话未读数显示为灰色）。如果会话里有进行中的会议，行内显示红点和会议名。
- 聊天区：会话头有成员头像组、语音、视频会议、详情按钮。有进行中的会议时，会话头下方出现「加入」横条，只占一行。置顶公告和 v1 一致。
- 消息：同一人同一分钟内的连续消息合并显示，头像、姓名、时间只出现一次。自己的消息只在最后一条下标「已送出」；发送中显示转圈；失败显示红色虚线框和「重试」。
- 文件：下载有进度和取消；对方发来的文件先显示「拒绝 / 选择位置并接收」，确认后才开始传输（对应 `file_ui` 的显式接收）；自己发的文件先放在输入框上方待确认，发出后可以撤回。
- 输入框：Enter 发送，Shift+Enter 换行，支持附件、表情、@，按会话保存草稿。
- 详情抽屉：成员、文件、免打扰、置顶。

### 会议

- 首页：立即开会、加入会议（9 位会议号校验）、进行中、最近结束。
- 会前检查：本机预览、麦克风音量条、扬声器测试、摄像头选择。摄像头未授权时给出提示和「打开系统设置」，仍可只用声音加入，不会反复弹窗。默认值取自 设置 → 音视频。
- 舞台：顶栏包含返回消息、会议名、网络质量、计时、布局（演讲者 / 宫格）、全屏。别人共享时，共享画面在左，人像条在右；说话人显示金色描边和声纹。
- **自己共享时**，顶部始终显示金色「你正在共享窗口「…」· 停止共享」条，舞台改为显示「其他人看到的画面」，避免出现画面无限嵌套；底部共享按钮变成「停止共享」。
- 坞：麦克风、摄像头（各带设备菜单）｜共享、参会人、聊天｜离开（靠右，红色）。「离开」弹出菜单：离开会议；主持人额外有「结束全体会议」。
- 重连：舞台顶部提示「会议信息已保留，麦克风和摄像头状态不变」；离线时提供「立即重试」。
- 共享选择器：窗口 / 整个屏幕切换，带缩略图卡片，未选择时「开始共享」禁用。选「整个屏幕」时显示风险提示；已有人在共享时提示会替换对方的画面。可以勾选共享系统声音并说明系统版本要求。Esc、取消、X 只关闭选择器。

### 通讯录

部门列表 → 成员列表（姓名 / 职位 / 状态）→ 资料卡（发消息、发起会议、邮箱、所在地、共同群聊）。从资料卡发消息会直接打开或新建私聊。

### 设置

账号与工作区、音视频、通知、网络与连接、关于与更新，底部单独放开发者诊断。预览版提示只放在「关于与更新」，不再在每页挂徽标。

### 全局

- ⌘K / Ctrl+K 快速跳转：搜索会话、成员（直接发起私聊）和常用操作。
- 宽度小于 1180px 时详情抽屉改为浮层；小于 980px 时会议坞只显示图标；小于 760px 时左侧导航变为底部标签栏，会话列表和聊天改为前进 / 返回两级页面（可作为 Android 版布局参考）。
- 键盘：所有控件可聚焦，焦点环可见；弹窗支持 Esc 关闭；开关和复选框支持空格 / 回车。系统开启「减少动态效果」时关闭声纹、说话人轮换等动画。

## 四、落地到 NSH 的建议顺序

1. **只改文案和空状态**（改动最小、收益最大）：把 `first_screen.rs` 里的说明性常量改成产品文案，会话栏去掉两行常驻状态，会议页去掉坞下方两行灰字。
2. **壳层调整**：删掉浅色页面顶部灰条，把隐私 / 网络状态并入标题栏胶囊；新增工作区切换浮层；登录流程从「成员」页移到启动流程。
3. **消息组件**：消息分组（头像 / 姓名 / 时间）、文件卡片、会议卡片、失败重试、草稿。需要的数据（发送者、时间）在企业信令里已经有，不需要新协议。
4. **会议流程**：先做会议首页和会前检查，再做舞台的共享 / 宫格两种布局和最小化迷你条。
5. **通讯录与设置**：在现有只读成员目录上增加部门分组和资料卡；设置按分类拆开。

在线状态、未读数、已读回执、会议号加入、系统声音共享这几项在稿中是体验提案，需要后端或平台能力支持后才能上线，实现时没有数据就不显示，不要用假值占位。
