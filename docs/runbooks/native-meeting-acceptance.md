# 原生企业会议：三账号验收

本手册用于集成包的候选验收，不是通过报告。所有端使用同一候选 SHA；在[证据模板](native-meeting-evidence.md)中分开记录真实 fork、macOS 同机、跨网络直连及授权 TURN。任一前置条件未满足，标记「未测」及原因，不把结果用于放行。

## 1. 现有账号与隔离

1. 用 ck-test-kit MCP 调用 `test_kit_rules` 和 `test_kit_list`；以 `workspaces[].slug == "devin-p2p-ws"` 精确核对未过期主体。列表只显示本 agent 的已绑定主体，不显示按邮箱待绑定的邀请；若不足三人，先请测试账号负责人用现有身份核对激活和邀请，不从相似 slug 推断成员，不重建账号。只有负责人确认第三个现有账号且核准时，才按[测试物料手册](test-kit.md)补普通成员邀请。按 A（确认是普通成员，主持）、B、C（另外两位，允许一位是 Owner）建立仅测试员可见的对应表；列表不证明真实登录成功。
2. **同机**：准备一台经批准的 Apple Silicon Mac，创建三个独立的本机测试用户，每个用户分别安装或访问同一 SHA 的企业候选包。每个用户使用独立的正常浏览器 profile（不共享同步账号、Cookie 或旧 Safari 会话），验证系统默认浏览器确实打开该用户的 profile。使用快速用户切换保留客户端进程，不退出其余会话。每个用户的客户端目录应分别位于自己的 `~/Library/Application Support/top.maplayer.collaboration`；不要共用 HOME、浏览器或目录。未能维持后台客户端或同时访问设备时，保留同机拓扑结果，真实多端收发转到独立设备；合成媒体不能补足真实设备验收。
3. **跨网络**：准备三台支持候选包的 Mac，每台配一套麦克风、摄像头、耳机和可共享的无敏感信息测试窗口；至少跨两个经批准的网络，以 A/B 在同一测试网络、C 在另一网络为例。分别记录网络/设备代号、OS 版本和测试场景，不保存地址。在各端确认系统媒体权限正常。镜头用 A/B/C 字样作为区分，语音用代号轮流报数，共享窗口用可变计数器区分静态截图；不使用生产资料或真实客户画面。
4. **登录顺序**：A 完成 IdP 回调并在应用内确认实际主体、`devin-p2p-ws` 和成员角色后，再启动 B 登录，B 完成后才启动 C。桌面端回调端口固定，禁止同机同时发起；如回调失败或第二端静默进入第一端账号，暂停该轮，注销错误会话并更换隔离 profile。取证不录登录、浏览器地址栏或回调。另预留同 SHA 默认预览包做禁用回归，不改更新门禁。

## 2. 候选与测试 schema

1. 从集成负责人领取完整候选 SHA、企业包构建回执/哈希、同 SHA 默认预览包、A 交付的会议迁移文件名及真实 fork 测试入口。用发布回执固定公司 SurrealDB fork 的版本和哈希；不用 vanilla、`latest` 或生产账号跑本地 fixture。
2. 在可信源码 checkout 中，用 Python 3.10+ 运行预检（只读 Git 对象，不读取 env 或连接数据库）：

   ```sh
   python3 scripts/native-client/meeting-schema-preflight.py \
     --candidate "$CANDIDATE_SHA" --migration "$MEETING_MIGRATION"
   ```

   记录候选 SHA、会议迁移名、迁移 SHA-256 及模板末版本。预检通过只表示候选包含这份版本化迁移，不表示数据库已迁移或支持 `meeting_v1`。
3. 在新建、隔离的本地 fork 测试库，使用候选的完整 workspace 模板和 A 的测试入口；fixture 建库与撤权可由维护会话执行，正反例走普通 RECORD，不能用 root 冒充。核对旧模板不开启会议；在新模板上测同一主体的幂等加入、容量竞争、撤权、跨 scope、定向 SDP、租约与硬过期。记录 fork 版本、候选、命令、退出码；本地 fixture 不是实际 OIDC 证据。
4. 三账号实测优先用可由三人授权访问的独立候选环境，核对实际 workspace 的 `schema_version:current` 与迁移回执均对应同一 SHA，再用真实工作区身份确认 `meeting_v1`。若账号只在生产测试工作区有效，必须有明确授权和只针对 `devin-p2p-ws` 的发布路径、实际迁移审计及回滚方案。现有全工作区 [migration runner](../../server/src/db/migration-runner.ts) 不是单库工具；禁止手填版本或为验收提前迁移全体。没有隔离环境或限定发布授权就只跑本地 fork，保留三账号验收缺口。

## 3. 直连与限时授权 TURN

1. 先关闭所有端的 TURN（同机场景也不配 STUN；跨网只可用显式授权的 STUN），采集所有边两端选中 ICE 对的分类和 RTP 增量。候选列表、信令成功和 UI 自报不是选中路径证据。
2. 回退测试需要独立受控网络和测试专用 TURN 租约。向环境负责人预留服务、窗口与回收人；获取显式批准后，确认仅 A/C 可访问本轮中继，来源/转发范围限于测试网络，凭据为本轮两端各自短期凭据、到期不晚于授权窗口。通过安全渠道把凭据交给测试员，只在相应客户端的临时输入使用，不放入启动参数、配置仓、截图、终端记录或报告。证据只记批准记录、安全传递是否完成、有效窗口、注销结果。没有授权服务时不能换公共中继；标记授权回退未测。
3. 无 TURN 时，在**受控测试网络**只让 AC 的 host/STUN 直连路径不可用；保持 AB、BC 和 OIDC/WSS 可达，确认只有 AC 明示失败。恢复初始网络，重新建立三边直连基线。开启 A/C 的授权配置后，用相同的单边故障条件重新验证：AC 初轮仍先试直连，失败后该边进入新一轮，AC 两端选中 `relay` 且 RTP 恢复，AB/BC 保持 `direct` 且媒体不中断。另在一端缺少授权配置时确认不会误报可中继。若测试网络无法只影响一条边，标记此项未测，不用全局断网代替。
4. 测毕撤销租约与临时访问规则，确认无活动分配并恢复测试网络。独立报告实验室、跨 NAT、公网/生产 TURN 三种覆盖；不能用实验室中继证明公网可用。

## 4. 执行顺序与放行

1. 媒体关闭时 A 建会邀请 B/C；B 从邀请加入，C 凭会议号加入。三端各看到其余两人并建立 AB/AC/BC，无需逐边接受或聊天 DataChannel。三端分别发送可辨别的音视频；A 显式选窗口共享，B/C 同时可见，停止后两端分别确认画面移除。
2. C 离开、再入会，只删除和重建 AC/BC，确认 AB RTP 继续增长且无重新协商；旧入会实例和迟到 SDP 不恢复边。测试以普通成员身份主持、非主持人尝试结束、主持人结束、断网/续租/到期、切工作区、注销和退出。退出或失权时先停止本机发送，未确认设备停止应显示隐私警告。主持人断网只在租约到期回收该成员，不立即踢其他人。
3. 跑 A 的真实 fork 正反例和 C/F 的三端真实 UDP 压测及资源回收，再跑原生企业 OIDC 双人聊天及默认预览禁用回归。按证据模板填写每项结果、证据与缺口；看不到选中 ICE 对、真实 RTP 双向增长或设备回收，不标记通过。未完成三账号必测项不得合并；跨 NAT 或生产 TURN 未覆盖的场景单列，不扩大结论。
