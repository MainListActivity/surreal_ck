# 协作原生客户端设计基础

目标：桌面 Linux/macOS/Windows 与 Android 原生视图，不使用 WebView。先做真实可用状态，再接聊天和传输，不用假成功状态。

- 颜色：暖白画布 `#FAF9F6`、主文字/会议舞台 `#161513`、品牌金 `#F5C542`，并通过 NSH theme 的 background/foreground/primary/input/muted_foreground 语义角色支持明暗主题。
- 控件：src/ui 管理按钮、输入框、导航项、筛选条和消息气泡；Android触摸尺寸至少48dp，桌面首版沿用宽松尺寸。
- 字号：分区标题约26–28、正文14–16；间距以 8px 为基线，避免把标题和说明挤成一行。圆角 8–12px（theme.radius）。
- 布局：左侧导航宽 76px，图标在上、短标签在下（消息 / 会议 / 通讯录，底部设置）；窗口宽度小于 960px 时改为底部标签栏。消息页会话栏 300px，其余空间给聊天内容；会议、通讯录、设置、诊断是居中的内容页，最大宽度 760px。这是协同客户端，不是数据控制台。
- 窗口：标题为「吉吉 · 团队协同」。Linux/Windows 使用系统窗口装饰，不绘制伪造的 macOS 交通灯。侧栏品牌标是现有 Logo.svelte 几何（brand.svg），以内禀 256 渲染后再缩到侧栏尺寸，避免发糊的深色小方块。
- 动效清单：按钮hover/pressed透明度反馈；连接状态更新只反映真实传输事件；尊重减少动态效果，不添加无意义等待动画。
- 未完检查：明暗主题截图、平台键盘焦点、移动端安全区和返回行为需在实际窗口/模拟器验证。
- 数据：未接传输时保持离线，草稿明确标记仅当前会话、未发送、不持久化。不生成示例联系人、假消息、假在线人数或假会议。

## 产品壳层（H-04，按 docs/design/collaboration-client-v2 改版）

- 文案写给使用者：说明现在能做什么、下一步去哪，不在界面上复述「不会模拟登录」「不会生成示例联系人」一类工程约束；这些约束保留在代码与测试中。
- 状态集中：未连接、也没有媒体时，页面顶部不显示任何状态条。有连接、正在关闭或媒体未确认关闭时，在内容区顶部出现一条状态条，包含会话状态、采集状态和「断开并停止媒体」。开发者诊断页始终显示这条状态条，并放在滚动区之外。
- 消息页：会话栏为标题、搜索、全部 / 未读 / 群聊分段控件；没有会话时用图标 + 标题 + 一句说明的空状态。已配置但未登录时，提供「登录企业账号」按钮跳到通讯录。聊天区未连接时显示「选择一个会话开始聊天」；连接后显示会话头。连接失败时显示一行警示条。气泡：我发出的用半透明品牌金，对方的用卡片色加描边，并标注「对方」。只有自己的消息显示「发送中… / 已送出 / 发送失败，可再次发送」，不显示已送达或已读。未接线的附件和表情按钮直接隐藏，不再以禁用态占位。
- 会议页：浅色会议首页，包含「开始新会议」「加入会议」两张入口卡片，下方是「进行中」列表。会议能力接入前，两个入口都禁用，并用一行文字说明原因（未接入登录 / 未登录 / 未进入工作区 / 正在接入）。不再显示空的深色舞台、禁用的会议坞和仅供预览的共享选择器。
- 通讯录：标题下一行显示当前账号与工作区；成员摘要卡片下方是企业账号面板（登录、工作区切换、只读成员）。
- 设置：关于（品牌标、版本、预览说明）、软件更新（仅预览渠道）、高级（开发者诊断入口）。诊断内容保持原样，只能从设置进入。
- 颜色全部来自 theme.json 的语义角色。新增 card、accent、sidebar、destructive 等明暗两套取值，页面不再写死浅色值。

## 首屏信息架构（H-02）

- 产品主路径是企业身份、会话与消息；手动 P2P、STUN/TURN、连接指纹和媒体/文件调试在「设置 → 打开开发者诊断」。
- 真实状态：未配置、未登录、加载中、空列表、离线、连接失败、发送中、已送出、发送失败。
